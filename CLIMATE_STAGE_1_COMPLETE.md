# Температурная система - Этап 1: Реализовано

## Структура пакетов
```
com.trd.climate/

│   └── ModAttachments.java          # Регистрация Data Attachments
├── calculation/

│   └── TemperatureHudOverlay.java       # HUD отображение
```

## Реализованные компоненты

### 1. PlayerTemperatureData (Data Attachment)
- **Хранение**: через NeoForge Data Attachment API
- **Поля**:
  - `currentTemp` - текущая температура тела (°C)
  - `targetTemp` - целевая температура среды (°C)
  - `shelterLevel` - уровень укрытия от ветра (0.0-1.0)
- **Сериализация**: через Codec
- **Состояния**: 7 состояний от обледенения до перегрева

### 2. TemperatureCalculator - Математическая модель
**Формула базовой температуры:**
```
T_target = T_биома + ΔT_высота + ΔT_погода + ΔT_вода
```

**A. Температура биома:**
```java
T_биома = 20.0 + (vanillaTemp - 0.8) × 20.0
```
- Ice Spikes (-0.5) → -6°C
- Snowy Plains (0.0) → 4°C
- Plains (0.8) → 20°C
- Desert (2.0) → 44°C

**B. Влияние высоты:**
- Выше Y=64: каждые 10 блоков вверх → -1°C
- Ниже Y=64: стабилизация к теплу (+15°C в глубине)

**C. Погода и время суток:**
- Ясный день: +3°C
- Ясная ночь: -4°C
- Дождь: -6°C
- Гроза/Метель: -10°C

**D. Вода:**
- В холодной среде (<20°C): -8°C (переохлаждение)
- В жаркой среде (>25°C): охлаждение до 18°C

**Тепловая инерция тела:**
```java
T_current = T_current + (T_target - T_current) × 0.025
```
Игрок остывает/нагревается постепенно за 40-60 секунд.

### 3. Серверная логика (PlayerTemperatureTickHandler)
- **Частота обновления**: 1 раз в секунду (20 тиков)
- **Оптимизация**: уникальный сдвиг для каждого игрока `(tickCount + playerId) % 20`
- **Процесс**:
  1. Расчет целевой температуры среды
  2. Применение тепловой инерции
  3. Отправка пакета клиенту

### 4. Сетевая синхронизация
- **Пакет**: `SyncTemperaturePayload` (Server → Client)
- **Payload**: `currentTemp`, `targetTemp`
- **Кодек**: StreamCodec с ByteBufCodecs.FLOAT
- **Регистрация**: через `RegisterPayloadHandlersEvent`

### 5. Клиентский HUD
- **Позиция**: слева от центра, над полоской здоровья (x: screenWidth/2 - 91, y: screenHeight - 49)
- **Формат**: "20.0°C"
- **Цвет**:
  - Синий (0x55AAFF) - холод (<15°C)
  - Белый (0xFFFFFF) - комфорт (15-25°C)
  - Красный (0xFF5555) - жара (>25°C)
- **Регистрация**: через `RegisterGuiLayersEvent`, слой над `PLAYER_HEALTH`

## Баланс температурных состояний

| Диапазон (°C) | Состояние | Эффекты (будущая реализация) |
|--------------|-----------|------------------------------|
| < 0.0        | FREEZING  | Урон здоровью, ледяная виньетка |
| 0.0 - 10.0   | SEVERE_COLD | Slowness I, дрожание рук |
| 10.0 - 15.0  | COLD      | Звуки дрожи, медленное восстановление сытости |
| 15.0 - 25.0  | COMFORTABLE | Нормальное состояние |
| 25.0 - 32.0  | HOT       | Ускоренный расход голода/жажды |
| 32.0 - 40.0  | HEAT_STROKE | Weakness, размытие экрана |
| > 40.0       | OVERHEATING | Урон здоровью, шанс загореться |

## Производительность

- **Нагрузка на сервер**: минимальная
  - 1 расчет на игрока в секунду
  - Простые арифметические операции
  - Без рейкастов и сложных проверок

- **Сетевой трафик**: ~8 байт на игрока в секунду (2 float)

- **Нагрузка на клиент**: нулевая
  - Один простой текст в HUD
  - Без партиклов и сложного рендеринга

## Тестирование

Система успешно компилируется. Для тестирования в игре:

1. Запустить клиент: `./gradlew runClient`
2. Создать мир и следить за HUD в левом верхнем углу
3. Проверить изменение температуры:
   - Подняться в горы (температура должна падать)
   - Войти в воду в холодном биоме (резкое падение)
   - Перейти из равнин в пустыню (постепенный рост)
   - Дождаться ночи (снижение температуры)
